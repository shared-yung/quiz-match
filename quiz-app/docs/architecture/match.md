# match feature の構成

room（ルーム）・quiz（出題）・net（通信）をつないで、1回の対戦を組み立てる feature。置いた理由は [ADR 0005](../adr/0005-match-feature.md)。

## 依存の向き

```
match ──→ room   ルームの正本と参加の判断、ルールの編集フォーム・表示
      ──→ quiz   出題の進行と得点、ホストの出題操作の画面
      ──→ net    接続、ロビー（参加・再参加）、プロトコルのメッセージ
```

room・quiz・net は互いを知らず、match も知らない。ドメインの型と回線の型（`room/state` など）の変換は match の infrastructure にある。

## 層ごとの中身

| 層             | 中身                                                                                                                                                                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| use-case       | `createHostMatch`（ホスト）、`createPlayerMatch`（プレイヤー）、port の `Matchmaking`、プレイヤーから見たルームの様子 `RoomView`                                                                                                                                          |
| infrastructure | `toRoomStateMessage` / `toGameProgress`（`Room` と出題の進み具合 → `room/state`）、`toRoomView`（`room/state` → `RoomView`）、`createQuestionBroadcaster`（出題の通知 → 回線のメッセージ）、`toQuestionProgress`（途中参加に送り直す公開済みの部分）、`createSystemTimer` |
| presentation   | ホスト用・参加用の Pinia ストア、`HostMatchPanel` / `JoinMatchPanel`、`Matchmaking` の provide / inject                                                                                                                                                                   |
| install.ts     | `Matchmaking` の実装を組み立てて provide する。変換・ID の生成（`generateRandomId`）・タイマーにどの実装を使うかはここに閉じる                                                                                                                                            |

domain は今のところ中身が無いので置いていない。

### ホスト（`createHostMatch`）

- room の `RoomSession` でルームを持ち、net の `HostLobby` で接続をプレイヤーとして迎える。参加の可否はルームに任せる
- 参加者が増減するたびに、全員へ `room/state` を配る
- 参加・再参加した本人には、`join/accepted` に続けて途中経過（`catchUpMessages`）を送る
- quiz の `QuestionSession` で出題を進め、その通知を `createQuestionBroadcaster` で回線のメッセージにして配る。`room/state` の得点と状態も出題から作る
- 出題中に参加・再参加した本人には、公開済みの文字（一時停止中なら停止も）を送り直す
- プレイヤーからの `buzz` / `answer` はまだ受け付けていない（#23 でつなぐ）

### プレイヤー（`createPlayerMatch`）

- net の `PlayerLobby` で参加・再参加する
- ホストから届く `room/state` を `RoomView`（参加者とルール）にして持つ。読めないものは捨て、前の様子を保つ

## 画面

| 画面    | 中身                                                                                                                                                                                                   |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/host` | ルールの編集フォーム → ルームを作る → ルールの表示、出題（問題文の入力、公開の開始・一時停止・再開、公開した位置、次の問題へ）、参加者と接続状態、招待（招待の文字列とプレイヤーからの返事のやり取り） |
| `/join` | 表示名 → ホストの文字列を貼って返事を作る → 参加の状態、参加者、ルール                                                                                                                                 |

ルールの入力の妥当性は、ドメインの `ruleSetSchema` だけで判断する。画面に同じ規則を書き写さず、検証エラーの位置から誤りのある欄に印を付ける（`useRuleSetForm`）。

招待の文字列のコピーには Quasar の `copyToClipboard` を使う。Clipboard API は secure context でしか使えず、LAN 内の別端末から http で開くと動かないため、`execCommand` に落とせるものを選んだ。

## 手動での確認

1. `bun run dev` で起動し、`/#/host` を1タブ、`/#/join` を人数分のタブで開く
2. ホストでルールを決めて「この設定でルームを作る」
3. プレイヤーは表示名を入れて「この名前で参加する」
4. ホストで「プレイヤーを招待」→ できた文字列をプレイヤーの「ホストから受け取った文字列」に貼って「返事を作る」→ できた文字列をホストの同じ招待の枠に貼って「受け取る」
5. ホストの参加者一覧に名前が「接続済み」で出て、各プレイヤーの画面に参加者とホストが決めたルールが出る

6. ホストの「出題」で問題文を入れて「この問題にする」→「公開を始める」。公開した位置（`n / N 文字を公開`）が進む。「一時停止」で止まり、「再開」で続きから進む。全文を公開して猶予が過ぎると問題が終わり、「次の問題へ」で次を入れられる

プレイヤーの画面に問題文が出るのは #24 から。それまでは、届いたメッセージを net のデバッグ画面などで確かめる。

切れたプレイヤーは、ホストに新しく招待してもらい、同じ画面で 4 の手順を踏むと同じプレイヤーとして戻る。

## 決めていないこと

- 問題を出し切ったかどうか（[ゲームルール](../spec/game-rules.md)の「決めていないこと」）。決まるまでは出し切らない扱いで、`allQuestions` のゲームは終わらない

- ホストが画面を離れるとルームは閉じる（Pinia のストアを空にし、接続を閉じる）。ルームを残したまま他の画面へ移る必要が出たら見直す
- 参加中のプレイヤーをホストが外す操作（[ゲームルール](../spec/game-rules.md)の「決めていないこと」）
