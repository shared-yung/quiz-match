# P2P メッセージプロトコル

ホストとプレイヤーの間でやり取りするメッセージの一覧。**[ゲームルール](game-rules.md)の状態遷移と対になる。**

## 前提

- トポロジは**ホストを中心とした星形**。プレイヤー同士は直接つながらない
- 受信したメッセージは**必ず zod で検証**し、不正なものは破棄する。相手のクライアントは改造されうる
- 型定義は `src/shared/` に置く（#12）。通信層とドメインの境界になる

## 設計上の要点

**問題文の全文をプレイヤーに送らない。** 1文字ずつ送る意味が消えるため。プレイヤーが持つのは「これまでに届いた文字」だけで、正解文は問題終了時に初めて開示する。

**プレイヤーは自分の状態を主張しない。** 「押した」「回答した」を送るだけで、採用されたかどうかはホストからの通知で知る。ロックアウトや順序の判定はすべてホスト側にある。

**時刻はホストの時計で扱う。** 制限時間の締め切りはホストが絶対時刻で通知し、プレイヤー側は表示にのみ使う。判定はホストが行う。

## Host → Player

| メッセージ             | 送る時機                        | ペイロード                                  |
| ---------------------- | ------------------------------- | ------------------------------------------- |
| `room/state`           | 参加時、参加者の増減時          | 参加者一覧、RuleSet、現在の得点、ゲーム状態 |
| `question/start`       | `ready` → `revealing`           | 問題番号。**問題文は含めない**              |
| `question/char`        | 公開中、`revealIntervalMs` ごと | 位置と1文字                                 |
| `question/reveal-stop` | 早押し受理、または手動停止      | 停止理由                                    |
| `buzz/accepted`        | 早押しを採用したとき            | 採用したプレイヤー、回答の締め切り時刻      |
| `buzz/rejected`        | 押下を却下したとき              | 理由（先着に負けた / ロックアウト中）       |
| `judge/result`         | ホストが判定したとき            | 対象プレイヤー、正誤、次の状態              |
| `score/update`         | 得点が変わったとき              | 全員の得点                                  |
| `question/end`         | `closed` に入ったとき           | **正解文**、終了理由                        |
| `game/end`             | 勝利条件を満たしたとき          | 最終得点、勝者（引き分けなら複数）          |

## Player → Host

| メッセージ | 送る時機         | ペイロード   |
| ---------- | ---------------- | ------------ |
| `join`     | 接続直後         | 表示名       |
| `buzz`     | 早押しボタン押下 | なし         |
| `answer`   | 回答送信         | 回答テキスト |

プレイヤーから送るのはこの3つだけ。**状態を変える権限はホストにしかない。**

## 破棄するメッセージ

次は無視する。エラーを返さない（改造クライアントに情報を与えないため）。

- zod の検証に通らないもの
- 現在の状態で意味を持たないもの（`revealing` 以外での `buzz` など）
- ロックアウト中のプレイヤーからの `buzz`
- `buzz` が採用されていないプレイヤーからの `answer`
- 締め切りを過ぎた `answer`

## 拡張するときの注意

- **判別可能ユニオン**で定義する。メッセージ種別のフィールドで分岐できるようにする
- 追加するメッセージは、それが**どの状態で意味を持つか**をこの表に書く
- Player → Host を増やすときは慎重に。プレイヤー側に権限を渡すことになる

## 決めていないこと

- 再接続時の状態同期の粒度（#20 で決める）
- メッセージのバージョニング。クライアントの版が混在しうるかは配布方法が決まってから
